# 从 ARM 开始：用 HAL 控制一台闭环步进电机

适用项目：YS-F4Pro＋雷赛 57CME23＋CL57C。日期：2026-11-12。

这份教程从基本概念讲起，按“编译下载→GPIO→串口→定时器→电机→运动曲线→上位机”的顺序学习。最终目标是让电脑指定转数、速度、加速度、减速度和曲线类型，由 STM32 执行。

本文是学习与实施指南，包含局部示例、算法和调试步骤，不是已经烧录测试的完整工程。接线细节集中在[开发笔记](步进电机开发笔记.md)，动手前先读接线及版本说明。

## 1. ARM、STM32 和开发板有什么关系

### 1.1 ARM 是什么

Arm 提供处理器架构及处理器内核设计。可以先把“架构”理解为 CPU 理解哪些指令、程序如何与处理器交互的规则，把“内核”理解为执行这些指令的核心。

Cortex-M 是面向微控制器的内核系列。本项目使用的 Cortex-M4 属于这一系列。它能运行编译后的 C 程序，也能响应定时器、串口等产生的中断。[Arm Cortex-M4 介绍](https://www.arm.com/products/silicon-ip-cpu/cortex-m/cortex-m4)

### 1.2 STM32 是什么

ST 公司把处理器内核、Flash、RAM、定时器、串口和 GPIO 等放进同一颗芯片，构成 STM32 微控制器，也常叫 MCU 或单片机。

本项目的 STM32F407IG 使用 Cortex-M4 内核，最高主频为 168MHz。主频是 CPU 运行节奏，不意味着每个 GPIO 都能输出 168MHz，也不意味着电机脉冲应当使用这个频率。[ST 芯片介绍](https://www.st.com/en/microcontrollers-microprocessors/stm32f407ig.html)

| 名称 | 本项目中的含义 |
|---|---|
| Arm | 架构与内核设计来源 |
| Cortex-M4 | 芯片里面的处理器内核 |
| STM32F407IGT6 | 开发板上的 MCU 型号，以实物丝印复核 |
| YS-F4Pro | 带电源、接口、光耦等外围电路的板卡 |
| HAL | 控制 MCU 外设的软件库 |
| CL57C | 把脉冲指令转换为电机绕组电流的驱动器 |

### 1.3 程序保存在哪里

- Flash 保存固件，断电后通常仍保留。
- RAM 保存运行时变量，重新上电后需要重新初始化。
- 寄存器是控制和读取硬件状态的接口。

例如 `target_rpm = 30` 只是修改变量。必须由程序把这个数转换为定时器配置，硬件脉冲才会变化。

## 2. C、编译、下载、调试分别是什么

写下的 C 代码不能直接作为文字交给 MCU 执行。开发工具需要完成：

```text
.c/.h 源码 → 编译 → 链接 → 固件文件 → 下载到 Flash → MCU 执行
```

`.c` 放函数实现，`.h` 放声明与共享定义。编译检查各源文件并生成目标代码；链接把目标代码和库组合起来，形成固件。ELF/AXF 通常还包含调试信息，BIN/HEX 常用于烧录。

“下载”在嵌入式开发里通常指把固件写进芯片。“调试”可以让程序暂停、单步运行、查看变量。电机运行时打断点会影响控制流程，首次调试应先空载，避免在运动状态随意暂停 CPU。

准备好以下工具即可开始，不需要同时掌握全部工具：

1. STM32CubeMX 或具备配置功能的开发环境：选择引脚、时钟及外设。
2. 工程匹配的 IDE/编译器：原厂 Keil 工程可先在 Keil 中打开；新建工程也可使用 STM32CubeIDE。
3. ST-Link 等支持 SWD 的调试器及对应驱动。
4. USB 数据线、串口工具、万用表；检查脉冲最好有示波器或逻辑分析仪。

SWD 主要连 SWDIO、SWCLK、GND，并按调试器要求连接目标参考电压。目标参考电压不一定是给板卡供电的输出；先确认调试器定义，不要把 5V 接到 3.3V 信号上。板上 PA13/PA14 用于 SWD，保留调试功能。

第一项练习：复制一份匹配板卡的现有 HAL 工程，先不接电机，编译并下载一个简单程序。成功标准是调试器能识别芯片、程序能运行到 `main()`。

## 3. HAL 库解决什么问题

假设要改变一个引脚电平，最终必须设置 GPIO 寄存器。HAL 把常见寄存器操作封装成函数，例如：

```c
HAL_GPIO_WritePin(GPIOD, GPIO_PIN_3, GPIO_PIN_SET);
```

含义是把 PD3 写为高电平。前提是 GPIOD 时钟已经打开，PD3 已经配置为输出。仅复制这一行不能代替初始化。

HAL 是 ST 的硬件抽象层，常与 CMSIS、启动文件和芯片头文件一起使用。CMSIS 提供 Cortex 内核相关的软件接口，HAL 提供较高层的外设接口。[STM32CubeF4 说明](https://www.st.com/resource/en/user_manual/um1730-getting-started-with-stm32cubef4-mcu-package-for-stm32f4-series-stmicroelectronics.pdf)

常见工程入口如下，名称可能随工程结构变化：

```c
int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_USART1_UART_Init();
    MX_TIM8_Init();

    while (1) {
        /* 处理命令、状态和后台任务 */
    }
}
```

`HAL_Init()` 初始化 HAL 基础设施；`SystemClock_Config()` 设置时钟；`MX_..._Init()` 是配置工具常用的外设初始化命名。原厂工程可能使用 `STEPMOTOR_TIMx_Init()` 等自己的名称，不能只改函数名就当作迁移完成。

使用 CubeMX 生成工程时，把自定义代码放在受保护的 `USER CODE` 区域或独立文件中，避免重新生成时丢失。

## 4. 先认识 GPIO 和复用功能

GPIO 是通用输入输出引脚。PD3 表示 D 端口的第 3 根引脚。

- 输入模式：读取开关、电平。
- 输出模式：程序控制高低电平。
- 复用模式：由定时器、串口等外设控制引脚。

本项目中，PD3 用普通输出控制方向；PI5 用复用模式连接 TIM8_CH1。PI5 若误配成普通输出，即使 TIM8 在计数也不会自动产生预期波形。

板上还有光耦。MCU 引脚上的高电平不一定等于驱动器输入端上的高电平，必须沿着原理图看完整电路。CN16 的“+”也不代表可以接任意正电源。

练习：不接驱动器，配置 PD3 为推挽输出，用万用表验证改变 GPIO 状态时电压有变化。不要先用电机反应来判断一个 GPIO 是否正确。

## 5. 步进电机为什么能按脉冲转动

驱动器给两组绕组按顺序通电，形成旋转磁场，转子跟随移动。细分把一个整步分得更细，驱动器据此控制电流。

采用 PUL＋DIR 模式时：

- PUL：一个有效脉冲对应一个指令步。
- DIR：决定运动方向。
- ENA：控制驱动状态，具体逻辑以驱动器为准。

这里的有效脉冲不是任意一次电平翻转。方波从高到低再回到高才是一个完整周期。

假设驱动器设为 3200 指令脉冲/转：

```text
发 3200 个脉冲 → 指令转一圈
每秒发 3200 个脉冲 → 每秒一圈 → 60 rpm
```

细分指令分辨率与编码器分辨率不同。不要把编码器的计数直接作为 `pulses_per_rev`；后者由驱动器接收的每转指令脉冲数决定。

闭环表示 CL57C 会根据编码器反馈调节驱动。它仍可能在过载、接线错误或跟踪误差过大时报警，不能理解为任何工况都绝不会失步。

## 6. 按顺序完成接线

先断电，电机固定并保持空载或脱离危险机械机构。按[开发笔记第 3 节](步进电机开发笔记.md#3-第一轴硬件接线)逐根接线：

1. 电机动力线接驱动器 A/B 相。
2. 编码器线接驱动器对应反馈端口。
3. CN16 的 PUL、DIR 正负端分别接驱动器同名端。
4. 初期 ENA 两端悬空。
5. JP5、JP6 成对选板载 5V/GND，驱动器输入档选 5V。
6. 驱动器选单脉冲、闭环、3200 脉冲/转，软件也使用 3200。
7. 最后复查电源极性，再上电观察指示灯。

闭环相序错误时，不要通过大幅加电流强行解决。先停机查动力线与编码器线。

## 7. 定时器：让硬件稳定地产生脉冲

### 7.1 为什么不用 HAL_Delay 翻转引脚

`HAL_Delay()` 常用于毫秒级等待。主循环里反复翻转 GPIO 会受串口、计算及中断影响，也会阻塞其他任务。定时器可以按硬件时钟自动输出方波。

计数器不断增加，达到设定值后回绕或触发比较事件。重要参数包括：

| 参数 | 含义 |
|---|---|
| PSC | 预分频，决定计数节拍 |
| ARR | 自动重装值，决定计数周期 |
| CCR | 比较值，用于波形边沿或占空比 |
| CH1 | 定时器第一个输出通道 |

边沿对齐、向上计数 PWM 的频率为：

```text
计数频率 = 定时器输入时钟 / (PSC + 1)
PWM频率 = 计数频率 / (ARR + 1)
```

不能一律用 CPU 主频代替定时器输入时钟。本项目常用配置下 TIM8 可为 168MHz，TIM6 可为 84MHz，但必须核对本工程时钟树和 APB 分频。

### 7.2 一个只验证匀速脉冲的 HAL 示例

先在配置工具中完成：TIM8 使用内部时钟；CH1 使用 PWM Generation CH1；PI5 为 AF3；向上计数；PSC 为 167；ARR 为 624；CH1 Pulse 为 312；PWM1；极性先按配置验证；使能 ARR 预装载。这个例子要求 TIM8 输入时钟确实是 168MHz。

由此得到 1MHz 计数频率和 1600Hz 方波，对 3200 脉冲/转而言是 30rpm。还应检查 TIM8 的 Break、输出使能和初始化错误。

下列片段放在初始化完成后，只用于空载检查持续脉冲：

```c
/* htim8、GPIO 及 TIM8 PWM 已由工程初始化。
 * 驱动器 ENA 暂不接；本例不实现加减速或精确位置停止。
 */
HAL_GPIO_WritePin(GPIOD, GPIO_PIN_3, GPIO_PIN_RESET);
HAL_Delay(1);  /* 本次只在启动前等待方向稳定 */

if (HAL_TIM_PWM_Start(&htim8, TIM_CHANNEL_1) != HAL_OK) {
    Error_Handler();
}
```

需要停止测试时：

```c
HAL_TIM_PWM_Stop(&htim8, TIM_CHANNEL_1);
```

停止后的引脚电平需要在驱动器端测量，避免额外有效边沿。不要用“运行一秒再停止”作为精确一圈的实现，它没有精确计数，也可能受启动相位影响。首次先用示波器测频率，再连接并运行电机。

### 7.3 PWM 与输出比较翻转模式

PWM 适合理解匀速方波。原厂步进例程大量使用输出比较：每次比较事件安排下一次边沿，便于逐脉冲变速和位置计数。

翻转模式下：

```text
完整脉冲频率 = 计数频率 / (2 × 相邻翻转间隔计数)
```

不要把 PWM 的 ARR 公式直接套进翻转模式。16 位定时器可表示的最大间隔也有限，极低速需要选择合适分频或扩展等待策略。若计数频率为 1MHz，单次间隔计数不能直接写入超过 65535 的数。

## 8. 先让电机匀速，再做精确位置

推荐检查顺序：

1. 驱动器无报警，电机上电处于正常保持状态。
2. 输入端有 1600Hz 波形，宽度及电压满足要求。
3. 空载低速转动，停止后修改 DIR，再启动确认反向。
4. 在脉冲引擎中累计有效指令脉冲，到 3200 后停在完整周期边界。
5. 在轴上做标记，检查是否一圈，重复多次看有无累计偏差。

不能在最后一个脉冲中途直接停输出，否则可能破坏最小脉宽。位置计数、有效沿、停止状态必须统一设计。不要在方向未稳定时马上发第一个脉冲。

## 9. 梯形加减速：让速度逐渐变化

直接从静止跳到高脉冲频率可能造成机械冲击或跟踪报警。梯形曲线包含加速、匀速、减速三段。

先统一为脉冲单位：

```text
v = rpm × P / 60              单位 pulse/s
a = 加速度rpm/s × P / 60      单位 pulse/s²
d = 减速度rpm/s × P / 60      单位 pulse/s²
```

其中 P 是每转指令脉冲数。以从静止起步并最终停止的运动为例：

```text
加速距离 = vmax² / (2a)
减速距离 = vmax² / (2d)
```

若目标总脉冲数足够长，中间可以匀速。若不足以加到 vmax 再停下，应降低峰值速度，形成三角形曲线：

```text
vpeak = sqrt(2 × 总脉冲数 × a × d / (a + d))
```

例如 P=3200，目标转一圈，vmax=60rpm，a=d=60rpm/s：加速和减速各用 1600 脉冲，总计正好 3200，没有匀速段。

规划时需要检查：位移是否为零、a/d 是否大于零、速度是否超限、方向如何处理、浮点和整数是否溢出。将方向单独存储，距离规划使用非负幅值；处理最小有符号整数时避免直接取负溢出。

周期性规划的概念如下，不能直接替代完整脉冲调度器：

```text
每次控制周期：
    根据剩余距离和当前速度判断是否需要刹车
    若加速：v_next = min(v + a × dt, 目标速度)
    若减速：v_next = max(v - d × dt, 0)
    将速度交给脉冲引擎，更新下一次边沿时间
```

`v=0` 时不能计算 `1/v`。第一步如何启动、最后一步如何停止、低速如何排程，都由脉冲引擎处理。低频控制周期只更新规划状态，不能用 1ms 中断直接代替所有高频步进边沿。

读原厂 206 例程时，重点找移动入口、加减速状态、剩余步数和定时器中断。先确认其角速度与缩放单位，再写自己的 rpm 转换层。

## 10. S 型曲线：进一步减少冲击

梯形曲线中，加速度在各段边界会突然变化。S 型通过限制加速度的变化率，让加速和减速过程更平滑。这个变化率叫 Jerk，即加加速度。

常见七段曲线是：

```text
加速度逐渐增大 → 恒加速度 → 加速度逐渐减小
→ 匀速
→ 减速度逐渐增大 → 恒减速度 → 减速度逐渐减小
```

短行程时，一些段会缩短或消失。仅把速度做平滑滤波，并不能保证准确停在指定位置。

建议先运行原厂 253 的单轴 S 型思路，再统一参数接口；运行中改速需要重新规划，后续参考 254。不要同时把 206 与 253 的定时器初始化、中断和状态变量全部复制进一个工程。

速度曲线可以用日志检查：记录时间、指令速度、指令位置、状态；画图看是否连续，以及总脉冲数是否正确。曲线平滑不代表接线正确，也不代表实际轴完全跟随。

## 11. 串口和上位机如何协作

UART/USART 把字节按约定波特率发送。USB2 的板载芯片负责把电脑 USB 转成 MCU 串口；USART1 使用 PB6 TX、PB7 RX，JP2 要接通。驱动器本身的 RS232 调试口另有用途，不直接接 MCU 的普通 TTL 引脚。

先让电脑收到 `HELLO`，再处理运动。可以约定 115200、8 数据位、无校验、1 停止位；这是本教程建议的新协议配置，需要两端一致，不代表所有原厂例程默认如此。

### 11.1 首版协议建议

以下是待实现的新文本协议，不是 239 例程已有命令：

```text
PING\n
MOVE 3200 30 30 30 TRAP\n
STOP\n
STATUS\n
```

MOVE 参数依次为有符号相对脉冲数、目标 rpm、加速度 rpm/s、减速度 rpm/s、曲线类型。将来 S 型命令还需定义 Jerk 参数；没有定义前应明确拒绝，不悄悄忽略。

响应可以采用：

```text
OK PING
OK MOVE
ERR BUSY
ERR RANGE
STATE RUNNING 1200 30.0
DONE 3200
```

串口可能一次收到半条命令，也可能一次收到多条。程序应缓存到换行才解析，限制最长长度，过滤非法数字和非有限浮点值，并处理缓冲区溢出。中断只接收数据和通知主循环，不在中断里阻塞执行运动或打印长日志。

首版运动中仅接受 STATUS 和 STOP；重复 MOVE 返回 BUSY。普通 STOP 是减速停止；通信断开时执行什么动作需要提前确定。不要在首次联调中引入运行中任意改参。

### 11.2 一个最小电脑发送脚本

安装 Python 和 pyserial 后，可以先用脚本代替图形界面。此脚本只用于手动测试串口，要求固件已实现上面的协议：

```python
import serial

# 把 COM5 改成设备管理器中的实际串口。
with serial.Serial('COM5', 115200, timeout=1) as port:
    port.write(b'PING\n')
    print(port.readline().decode('ascii', errors='replace').strip())
```

运行命令为 `python 文件名.py`。安装包的命令为 `python -m pip install pyserial`。图形上位机再逐步加入串口选择、参数输入、启动/停止、状态栏和速度曲线。

不要直接用上位机界面每隔几毫秒发一次脉冲指令来代替 MCU 定时器。USB 与桌面操作系统的通信延迟不适合决定每个电机边沿。

## 12. 把固件分成容易理解的模块

```text
main.c               初始化与主循环
stepper_pulse.c/.h   脉冲输出、有效沿计数、方向及停止边界
motion_plan.c/.h     梯形/S 型规划与单位换算
motion_state.c/.h    IDLE/RUNNING/STOPPING/FAULT
protocol.c/.h        串口缓存、命令解析与参数检查
telemetry.c/.h       状态及曲线数据发送
```

文件名是建议，可以适应现有工程。先做一轴，不必一开始引入 RTOS。

中断与主循环共享变量需要考虑并发。`volatile` 只限制编译优化，不保证多字段更新的一致性，也不能替代临界区。更新一组运动参数时，应使用短临界区或明确的消息交接机制，避免中断读到半组参数。

如果故障输入、机械限位尚未接入，就明确标记功能未实现。不能为了让界面完整而显示假的“无报警”或“已回零”。上电将指令位置置零，仅表示软件计数起点，不代表机械已经回到原点。

## 13. 按阶段验收，出问题先回到上一阶段

| 阶段 | 实际操作 | 通过标准 |
|---|---|---|
| 1 | 编译、SWD 下载 | 能运行到 main |
| 2 | GPIO 控制 | PD3 电平可测量变化 |
| 3 | USB2 串口通信 | PING 有正确响应 |
| 4 | 定时器输出 | 驱动输入端频率和脉宽正确 |
| 5 | 空载低速 | 正反转正常且无报警 |
| 6 | 定长运动 | 指令 3200 脉冲约转一圈 |
| 7 | 梯形与停止 | 长短行程正确，STOP 能减速停 |
| 8 | S 型 | 段间变化合理且脉冲总数正确 |
| 9 | 上位机曲线 | 参数、状态、指令曲线一致 |

## 14. 常见故障怎么查

| 现象 | 优先检查 |
|---|---|
| 无保持力、不转 | 驱动供电、报警及 ENA 是否使其脱机 |
| 有保持力但不转 | PUL 波形、5V 输入档、JP5/JP6、TIM8 输出 |
| 只向一个方向转 | DIR 接线与电平、单脉冲模式、方向建立时间 |
| 转数倍数不对 | 驱动细分与软件 P 值、是否把翻转次数当脉冲数 |
| 一启动就报警 | 动力/编码器相序、反馈连接、加速是否过快 |
| 发串口时抖动 | 中断阻塞、临界区过长、脉冲由软件延时产生 |
| 看不到 COM 口 | 是否用 USB2、线缆是否支持数据、串口芯片驱动 |
| 上位机位置对但实际不对 | 显示是否只有指令计数，是否需要实际反馈 |

发生报警时先记录指示灯闪烁次数或故障码，再按实际版本手册排查。不要反复上电并继续提高速度掩盖问题。
