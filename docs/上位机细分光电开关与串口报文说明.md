# 上位机细分、光电开关与串口报文说明

日期：2026-11-12。对象：YS-F4Pro、现有四轴 v3 HAL 固件、CL57C 和 57CME23。

本次修改上位机，保持下位机代码、PROTO=3 和现有串口报文格式不变。用户已确认目前实际驱动器为 **1600 指令脉冲/转**。

## 1. 本次已实现与当前限制

| 项目 | 实现情况 |

| 每轴细分设置 | 可选择每转指令脉冲数，四轴分别保存到电脑 |
| 与驱动器匹配 | 用户手动设置驱动器，上位机勾选确认同值；不远程修改驱动器 |
| 转数、速度换算 | 按每轴细分换算界面、曲线、参数写入和回读 |
| 负限位、原点、正限位 | 每轴增加三个配置位置、计划输入映射、有效电平和状态显示区 |

“负轴 0 正”在本次设计中解释为：**负限位、原点、正限位**。输入映射是本机配置方案，当前不会写入下位机 GPIO 配置。

## 2. 细分指的是什么

界面使用“每转指令脉冲数”，即驱动器需要收到多少个 PUL 脉冲，电机轴才转一圈。它与编码器每转反馈计数不是同一个参数。

当前实际设置：

```text
驱动器：1600 脉冲/转
软件：1600 脉冲/转
发 1600 脉冲 → 指令一圈
发 3200 脉冲 → 指令两圈
30 rpm → 800 Hz
```

界面提供驱动器常见每转脉冲数选项。具体是否支持、如何拨码，仍以手上 CL57C 版本及其丝印/手册为准。上位机选项不是驱动器已成功配置的证明。

## 3. 同步设置的操作流程

1. 停止要修改的轴，确认机械处于适合调整的状态。
2. 按实际驱动器说明设置拨码或驱动器调试参数；需要断电设置时按其要求断电。
3. 在上位机选择对应轴，打开“细分与光电开关”页。
4. 选择与驱动器一致的“每转指令脉冲数”。
5. 勾选“驱动器已手动设为同值”，点击“应用本轴配置”。
6. 回到运动参数，检查位移、实际速度及加减速度，点击“写入参数”，等待板端回读一致。
7. 从小位移、低速度开始验证实际转数。

应用细分只保存电脑配置，不会自动发运动命令，也不会自动改变驱动器。改变细分后，原来的“脉冲数”不会自动翻倍；若希望保持一圈，可以将位移单位选择为“转”并输入 1。

本机细分与光电配置保存在：

```text
%LOCALAPPDATA%\YSF4Pro_Controller\settings.json
```

这个电脑配置可以跨上位机重启保留；板端 SET 参数仍在 RAM 中，断电恢复默认值。恢复非默认细分配置后，需要再次确认驱动器已设置为同值。

## 4. 保持报文不变时如何换算速度

下位机现有固件的计算参考值固定为 1600。这里保留该值与协议，不把它误当成所有驱动器当前的实际细分。

设驱动器实际每转脉冲数为 `P`：

```text
报文速度值 = 界面实际 rpm × P / 1600
报文加速度 = 界面实际 rpm/s × P / 1600
报文减速度 = 界面实际 rpm/s × P / 1600

界面实际 rpm = 报文速度值 × 1600 / P
指令转数 = 指令脉冲数 / P
```

例如驱动器改为 3200 脉冲/转，界面要求一圈、30rpm、加减速度各 30rpm/s，则原协议报文是：

```text
SET 1 3200 60 60 60 TRAP
GET 1
```

回读示例：

```text
PARAM 1 STEPS=3200 RPM=60 ACC=60 DEC=60 CURVE=TRAP REV=1
```

上位机会显示 30rpm 和 30rpm/s，而不是直接把原始的 60 显示为实际转速。启动仍发送原有的：

```text
RUN 1 1
```

由于原协议速度及加减速度参数只能是整数，本次不做有误差的静默取整。例如 800 脉冲/转时，界面速度需要是 2rpm 的整数倍，才能精确换算为原协议整数。

原固件边界仍生效：速度报文值 1～60、加减速度报文值 1～120、位移 1～32000 脉冲、单次运动不超过 120 秒。因此实际可设范围随细分变化，界面会提示：

| 驱动器每转脉冲数 | 实际速度范围 | 实际加减速度范围 |
|---|---|---|
| 800 | 2～120rpm | 2～240rpm/s |
| 1600 | 1～60rpm | 1～120rpm/s |
| 3200 | 0.5～30rpm | 0.5～60rpm/s |
| 6400 | 0.25～15rpm | 0.25～30rpm/s |

这不是扩展了机械设备的可用转速；它只是当前固件报文边界对应的数学范围。高细分时，一次 32000 脉冲可能不足一圈，本次不会自动拆成多个移动。

曲线、位置和速度仍是指令值，没有读取编码器实际反馈。

## 5. 三个光电开关

配置区按负限位、原点、正限位排列。每个位置可选择计划输入 IN1～IN12 和高/低电平触发。

建议的四轴规划如下，仅用于分配接口，尚未在下位机接入：

| 轴 | 负限位 | 原点 | 正限位 |
|---|---|---|---|
| 轴1 | IN1 | IN2 | IN3 |
| 轴2 | IN4 | IN5 | IN6 |
| 轴3 | IN7 | IN8 | IN9 |
| 轴4 | IN10 | IN11 | IN12 |

如果目前只有三个实物开关，可以先只配置一个轴；若四轴都各配一组，则共需十二个开关。软件映射不会替代实际接线。

接线前还需确认传感器型号、NPN/PNP、常开/常闭、供电电压和有效电平。暂未取得这些信息，不按线色猜接、不直接把传感器电源接到 MCU 引脚，也不在本次给出确定的三根线接法。

当前所有开关状态都显示“未知 · 当前报文不含输入状态”。不能据此推断机械没有碰到限位。

后续要实现真实状态及保护，需要安排下位机读取输入、去抖、限位方向处理和回原点状态机，并提供状态反馈。限位保护应在下位机执行，不能仅依赖电脑轮询。该工作需要单独确认固件及协议如何兼容扩展，本次保持报文不变，暂不实现。

## 6. 串口报文输入框

打开“串口报文 / 收发记录”页：

1. 手动输入命令，或点击“填入本轴 GET”“填入本轴 SET”“填入 STATUS”。
2. 检查命令轴号和值。
3. 点击“发送报文”，在通信记录中查看回复。

仅支持 ASCII，1～8 行，每条最多 110 个可打印字符。自动追加 LF，可以粘贴 CRLF。没有新增 HEX 或 Modbus 模式，也不创建新的下位机命令。

安全的查询示例：

```text
HELLO
GET 1
STATUS
```

以现有 1600 脉冲/转设置写入参数：

```text
SET 1 1600 30 30 30 TRAP
GET 1
```

手动发送区按原始报文单位发送，不再额外进行细分换算。“填入本轴 SET”会先从当前界面计算出正确的原始 SET 命令，填入但不发送。手工键入时需要自行理解上节换算规则。

原始 RUN 和 MOVE 会触发运动。手动报文不会经过运动面板的“参数同步后才启动”按钮限制，下位机仍执行其自身参数范围、忙状态和故障检查。

光电输入查询命令目前不存在。不要把无返回或 ERR COMMAND 当成开关未触发。

默认隐藏定期 STATUS 收发，避免刷屏；勾选“显示轮询报文”可查看。通信记录有容量上限，可用“导出通信记录”保存。
