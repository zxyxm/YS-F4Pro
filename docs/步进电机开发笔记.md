## 1. 本次目标与当前状态

使用 YS-F4Pro 控制雷赛 57CME23 电机及 CL57C 驱动器，实现正反转、定长移动、速度设置、独立加速度和减速度设置、梯形/S 型速度曲线以及电脑上位机控制。

目前已完成 HAL/CMake 单轴固件、DAP 连接、原 Flash 备份、编译刷写和 Flash 校验，并读回确认初始化与规划计算自检通过。尚未验证实际电机转数、波形或电脑串口联调；未自动启动电机。操作见[固件说明](../firmware/YS_F4Pro_Stepper/README.md)。“减速带”暂按减速度和减速段理解。

驱动器细节按 CL57C **2.0** 官方手册整理，实际版本、端子丝印、输入电平开关、配套电机参数仍需在实物上确认。57CME23 的完整后缀和线缆颜色定义尚未确认，不按颜色猜接线，也不在未核对铭牌时固定电流参数。

## 2. 系统分工

```text
电脑上位机 ──USB串口── STM32 HAL 固件
                           │ PUL / DIR / EN（可选）
                           ▼
独立直流电源 ────────── CL57C ──动力线── 57CME23
                           ▲                │
                           └────编码器线────┘
```

STM32 规划运动并产生脉冲；CL57C 驱动绕组，并读取电机编码器完成内部闭环。编码器优先接驱动器，不能用“接到开发板”代替驱动器所需反馈。开发板不直接供电机动力。

## 3. 第一轴硬件接线

依据 2025 版主板原理图第 5 页，第一轴使用 CN16。

| CN16 引脚 | 板端信号 | CL57C 对应端子 |
|---|---|---|
| 1 | EN− | ENA−，首次调试暂不接 |
| 2 | EN+ | ENA+，首次调试暂不接 |
| 3 | DIR− | DIR− |
| 4 | DIR+ | DIR+ |
| 5 | PUL− | PUL− |
| 6 | PUL+ | PUL+ |

不要照着两端“从左到右”接。两边端子排序不一致，要按名称逐根核对。

### 电源与跳线

- 2025 版 JP5 选择上方板载 5V，JP6 配套选择上方 GND；对应输出侧使用板载电源。以实物丝印和原理图为准，旧版板卡的方向可能不同。
- CL57C 2.0 脉冲/方向信号电压选择置 **5V**；电机电源和信号电源是两回事。
- CL57C 2.0 电源范围按手册为 24～50V DC，接 +VDC/GND。最终供电按实际版本铭牌确认，并给减速回生留电压余量。
- 开发板按其自身规格供电，不在未核对时共用驱动器高压电源；USB 数据连接不代表整套系统已具备足够供电。
- 不把 24V/36V 电机电源接到 CN16 的信号端。

### 电机与编码器

| 电机端功能 | CL57C |
|---|---|
| 动力 A+、A− | A+、A− |
| 动力 B+、B− | B+、B− |
| 编码器 A+、A− | EA+、EA− |
| 编码器 B+、B− | EB+、EB− |
| 编码器 5V、地 | VCC/E+5V、EGND |

优先使用匹配的原装动力及编码器线。万用表可以识别绕组配对，但闭环系统还需要正确相序，不能仅凭两根线导通便认定正负。所有接线和插拔在断电后进行。

### EN 的特殊含义

CL57C 2.0 默认配置下，ENA 输入导通表示电机断电自由；ENA 悬空可正常使能。初次运行先悬空 ENA，排除使能接反问题。

239 与 253 例程的使能宏电平相反，不能直接混用。结合板端光耦电路推导，在原理图对应接法和驱动器默认参数下，PD7 高电平使板端光耦导通，可能令驱动器脱机；最终以实测和实际参数为准。EN 不是安全急停回路。

## 4. HAL 外设安排

| 功能 | 外设/引脚 | 说明 |
|---|---|---|
| 第一轴脉冲 | TIM8_CH1 / PI5 / AF3 | 走板上光耦至 CN16 |
| 方向 | PD3 | GPIO 输出 |
| EN，可选 | PD7 | GPIO 输出，核对有效电平 |
| 上位机通信 | USART1 / PB6 TX、PB7 RX | 经 JP2 接板载 USB 串口芯片 |
| USB 数据口 | USB2 Mini USB | 不与 USB1 OTG 混淆 |

2025 原理图标注串口芯片 CH330N；开发手册部分表格沿用 CH340G 名称。以实物芯片和设备管理器为准，不因此更换 USART1 引脚。

## 5. 首次调试参数

以下拨码仅适用于 CL57C 2.0 对应手册：

| 项目 | 设置 |
|---|---|
| 3200 指令脉冲/转 | SW1 OFF，SW2 OFF，SW3 ON，SW4 ON |
| 闭环 | SW6 OFF |
| 单脉冲＋方向 | SW7 OFF |
| 输入信号电压 | 独立选择开关置 5V |

软件同步设置 `pulses_per_rev = 3200`。首次空载可用 30 rpm 目标速度、30 rpm/s 加速度、30 rpm/s 减速度做低速验证；这些是起步测试值，不是性能保证。确认动力线、编码器线及机械固定后再运行。

```text
f_Hz = rpm × pulses_per_rev / 60
30 rpm → 1600 Hz
60 rpm → 3200 Hz
1 转 → 3200 个完整脉冲
```

CL57C 2.0 手册给出的 DIR 提前时间至少 5μs，高低脉宽各至少 2.5μs。建议首次调试方向等待 20μs，并用示波器检查驱动器输入端波形。STM32 引脚和光耦输出的逻辑可能反相；输出比较翻转模式每两次翻转才是一整个脉冲。

## 6. 固件与上位机设计

模块建议分为 GPIO/定时器驱动、运动规划器、状态机、串口协议和遥测。

- 速度：rpm；加速度/减速度：rpm/s；S 型 Jerk：rpm/s²。
- 梯形：加速、匀速、减速；短距离时采用三角形曲线。
- S 型：限制加速度变化率；定长移动还要计算何时刹车，不能只给速度做平滑滤波。
- 状态：IDLE、RUNNING、STOPPING、FAULT。
- 首版运动中拒绝新的 MOVE；STOP 执行减速停止；FAULT 锁存错误。
- 上位机显示指令速度及指令位置；驱动器内部闭环不等于 STM32 已收到真实位置。
- 如需真实转速/位置，另行设计受支持的反馈通道；不能把差分编码器线随意并接到普通 MCU 引脚。

电脑连接开发板 USB2。CL57C 的 RS232 使用专用调试线进行驱动器配置；本方案的日常运动命令由电脑发给 STM32，再转为 PUL/DIR。

### 10.5 时钟树怎么看：8MHz 为什么能变成 168MHz

下面的红字标注图汇总了时钟来源、PLL 计算、总线分频、定时器时钟及 PLLQ 的注意事项，可与后面的说明对照阅读。

![STM32F407 时钟树红字标注图](../output/images/STM32F407-clock-tree-annotated.png)

时钟树表示时钟来源、选择、倍频、分频及最终去向。沿箭头查看；`Mux` 表示多选一开关，选中圆点表示使用哪一路。

| 名称 | 含义及用途 |
|---|---|
| HSE | 外部高速时钟，本板使用 8MHz 晶振 |
| HSI | 内部高速 RC 时钟，16MHz |
| LSE | 外部低速晶振，通常为 32.768kHz，常用于 RTC |
| LSI | 内部低速 RC 时钟，约 32kHz，供独立看门狗等使用 |

主 PLL 选择 HSE，当前主频计算为：

```text
HSE 8MHz → PLLM ÷8 → 1MHz → PLLN ×336 → 336MHz
                                            ↓ PLLP ÷2
                                     PLLCLK = 168MHz
                                            ↓ 系统时钟选择 PLLCLK
                                     SYSCLK = 168MHz
```

| 输出时钟 | 分频与结果 | 用途 |
|---|---|---|
| HCLK | SYSCLK ÷1 = 168MHz | CPU、AHB 总线、存储器和 DMA 等 |
| PCLK1 | HCLK ÷4 = 42MHz | APB1 外设 |
| APB1 定时器时钟 | PCLK1 ×2 = 84MHz | TIM2～TIM7、TIM12～TIM14 |
| PCLK2 | HCLK ÷2 = 84MHz | APB2 外设 |
| APB2 定时器时钟 | PCLK2 ×2 = 168MHz | TIM1、TIM8～TIM11 |

STM32F407 的 APB 分频为 1 时，该总线上的定时器时钟等于 PCLK；分频不为 1 时，定时器时钟为 PCLK 的 2 倍。因此以后计算 PWM 和步进脉冲频率，要使用对应定时器的时钟。例如本配置下 TIM8 使用 168MHz，再由定时器自身预分频器继续分频。

截图及当前 `main.c` 的 **PLLQ=4**，这一支输出 `336÷4=84MHz`。如果使用要求 48MHz 时钟的 USB OTG FS、SDIO 或 RNG，应将 **PLLQ 改为 7**，得到 `336÷7=48MHz`；这不会改变 PLLP 输出的 168MHz。当前 LED 练习尚未使用这些外设。

其他支路：RTC 用于日历计时，IWDG 为独立看门狗，PLLI2S 提供音频相关时钟，MCO1/MCO2 可以向引脚输出时钟供测量或其他芯片使用。图中显示一个频率，不代表对应外设已启用。

### 10.8 MDK 与当前工程有什么区别

MDK 是 Keil 的 ARM 开发工具套件，其常用集成开发界面叫 µVision。它与 VS Code 方案可以开发同一颗芯片，差别主要在工程管理、编译器、链接和调试工具。

| 项目 | 当前 VS Code 方案 | 常见 Keil MDK 方案 |
|---|---|---|
| 编辑器/界面 | VS Code | µVision |
| 工程配置入口 | `CMakeLists.txt` | `.uvprojx` |
| 编译器 | Arm GCC | Arm Compiler |
| 构建执行 | CMake + Ninja | µVision 内置构建 |
| 链接布局 | 通常为 `.ld` 链接脚本 | 常用 `.sct` 或 IDE 布局设置 |
| 调试下载 | Cortex-Debug + OpenOCD | µVision 的调试下载功能 |

大部分普通 HAL 应用代码可以共用。启动代码、链接脚本、编译器特有语法及工程配置需要与工具链匹配，不能只改工程文件扩展名完成转换。

### 11.1 STM32F407IGT6 芯片里面有什么

本板 MCU 型号是 **STM32F407IGT6**，属于 **STM32F4** 系列，使用 **LQFP176** 封装。176 是封装总引脚数，包含电源、地、复位等，不代表有 176 个 GPIO；该型号最多有 140 个 GPIO，实际可用数量还取决于板载电路及外设复用。

| 资源 | 含义 |
|---|---|
| Cortex-M4 内核，带 FPU | 执行程序，支持 DSP 指令和硬件单精度浮点运算，常写作 Cortex-M4F，最高主频 168MHz |
| 内部 Flash：1MB | 保存程序代码、常量等，掉电后仍保留 |
| SRAM：192KB | 运行时数据、变量、堆栈；包括 128KB 常规 SRAM 和 64KB CCM 数据 RAM |
| 备份 SRAM：4KB | 独立备份域资源，需要相应供电和配置 |
| 供电与 I/O | 开发板 MCU 通常工作于 3.3V；不能把芯片供电范围称为 CPU 内核电压，也不能将 5V 容忍理解为 5V 供电 |

SRAM 不是任意外设都能访问的一整块连续内存。特别是 CCM 不供 DMA 访问，DMA 缓冲区需要放在可访问的常规 SRAM 中。

**部分数字 I/O 支持 5V 容忍，并非所有引脚都支持。** 应按数据手册中的 FT 标记、引脚模式和使用条件核对；模拟输入等不能据此直接接 5V，GPIO 高电平输出也不会因此变成 5V。

| 内置外设 | 作用 |
|---|---|
| GPIO | 通用输入、输出，例如按键、LED、方向控制 |
| USART/UART、SPI、I2C、CAN | 与其他芯片或设备通信；部分接口仍需外接收发器或转换芯片 |
| SDIO | 连接 SD 卡等设备 |
| USB OTG | 在软件和硬件支持下作为 USB 设备或主机 |
| 3 个 12 位 ADC | 将模拟电压转换成数字量；三个 ADC 不等于只有三个输入通道 |
| 2 个 12 位 DAC 通道 | 将数字量转换成模拟电压 |
| 定时器 | 计时、PWM、输出比较、输入捕获及编码器接口等 |
| DMA | 在外设与存储器等之间搬运数据，减少 CPU 参与 |
| FSMC | 外接 SRAM、NOR/NAND Flash，以及兼容的并口 LCD 等；本型号名称为 FSMC |
| RTC | 日历与时间维护，需要适当时钟源及供电 |
| CRC | 循环冗余校验，帮助检测数据错误，不是加密 |

可以把芯片理解为：**CPU 内核 + 程序存储器 + 运行内存 + 多种外设控制器**。外设控制器集成在芯片内，U 盘、屏幕、串口转换芯片和电机驱动器等仍是芯片外部设备。

芯片参数以 [ST 的 STM32F407IG 产品说明](https://www.st.com/en/microcontrollers-microprocessors/stm32f407ig.html)和[对应数据手册](https://www.st.com/resource/en/datasheet/stm32f407ig.pdf)为准。资料目录中的 STM32F417 数据手册是相近型号参考，不能将其中所有特性直接当作 STM32F407 的特性。

### 11.2 JTAG、SWD 和硬石 DAP 仿真器

STM32F407 芯片支持 JTAG 和 SWD。按手册介绍，YS-F4Pro 的板载调试连接采用 SWD，本项目也使用 **硬石 CMSIS-DAP 仿真器，以 SWD 模式连接**。

| 接口 | 核心调试信号 | 理解方式 |
|---|---|---|
| JTAG | TCK、TMS、TDI、TDO；nTRST 可选 | 支持调试，也有边界扫描、扫描链等用途 |
| SWD | SWCLK、SWDIO | 用较少信号完成程序下载、断点、单步、寄存器和内存查看等常用调试 |

手册写的“JTAG 20 引脚、SWD 6 引脚”描述的是常见连接器/板端接口形式，**不是协议固定需要的信号数量**。调试连接还需要公共地、目标电压参考，通常也连接 NRST；SWO 是可选的跟踪输出。具体插针顺序按板卡和仿真器丝印核对。

两者能够完成本项目常用调试，但不能概括为所有功能完全相同。使用 SWD 后，未使用的 JTAG 专用复用引脚可以按需要配置为 GPIO；仍需保留 **PA13/SWDIO、PA14/SWCLK**，避免影响调试连接。在 CubeMX 的 `System Core → SYS → Debug` 中选择 **Serial Wire**。

本项目 VS Code 使用 Cortex-Debug + OpenOCD，配合 `interface/cmsis-dap.cfg`、`target/stm32f4x.cfg`。DAP 是下载调试通道，不等于板载 USB 转串口通道。

### 11.3 CH330：电脑怎样与开发板串口通信

板载 CH330 将 MCU 的 UART 逻辑电平串口连接到电脑 USB，电脑识别为串口设备，驱动异常时需安装匹配驱动。这里的逻辑电平串口不能直接当作 RS232 电气接口。

```text
电脑串口软件/上位机
       ↕ USB
板载 CH330 USB 转串口芯片
       ↕ TX/RX 逻辑电平信号
STM32 USART1（本项目 PB6/PB7，经 JP2）
```

串口适合输出日志、发送指令和回传数据。DAP 连接用于程序下载和断点调试；板载 USB2 串口用于日常上位机通信。两者的 USB 线和功能分别核对。

手册第 43 页写 CH330，第 44 页部分内容沿用 CH340G 名称；2025 版原理图标注 CH330N，以实际板卡芯片和设备管理器识别结果为准。

### 11.4 数据存储：内部 Flash、外部 Flash 与 U 盘

| 存储资源 | 本项目中的用途与区别 |
|---|---|
| STM32 内部 1MB Flash | 通常保存 MCU 应用程序和常量 |
| SRAM | 运行时临时数据，掉电后不保留 |
| 板载 W25Q128FVSIG | 外接 SPI NOR Flash，挂在 SPI2 上，可存参数、资源、日志等 |
| 外接 U 盘 | 通过 USB 主机功能访问的外部存储设备 |

W25Q128 的容量为 **128Mbit ÷ 8 = 16MB**，按二进制容量精确表述为 16MiB，不能误认为是 128MB。它是串行 Flash，不是机械硬盘，也不会接上线就自动成为电脑磁盘。

使用 U 盘需要对应 USB OTG 接口、主机模式、USB Host 大容量存储类软件、文件系统，以及正确的 VBUS 供电。**CH330 的 USB 转串口接口不能代替 U 盘主机接口。** 若要让电脑把开发板识别为 USB 磁盘，则属于 USB Device MSC 功能，需要另行实现。

### 11.5 寄存器、标准固件库和 HAL 的区别

以下三个写法表达的是相同目标：将 **PB0 输出置高**。前提是已使能 GPIOB 时钟，并将 PB0 正确配置为输出。

```c
/* 直接操作寄存器 */
GPIOB->BSRR = 0x0001;

/* 标准固件库（SPL） */
GPIO_SetBits(GPIOB, GPIO_Pin_0);

/* HAL 库 */
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_0, GPIO_PIN_SET);
```

直接寄存器写法需要理解芯片寄存器和位定义。标准固件库与 HAL 使用函数封装这些操作，API 和工程组织不同，不能在未配置相应库时随意混用。

HAL 全称 **Hardware Abstraction Layer，硬件抽象层**。本项目使用 HAL。CubeMX 根据图形配置生成 HAL 初始化代码，应用逻辑仍需要自己编写。

STM32CubeMX 官方安装包入口：[ST STM32CubeMX](https://www.st.com/en/development-tools/stm32cubemx.html)。软件安装与 F4 固件库安装是两项工作，具体辨别及工程生成设置见第 10 节。
